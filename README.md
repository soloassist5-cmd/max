# Школьный бот-помощник для MAX

Бот для мессенджера MAX: расписание уроков и звонков, домашние задания, оценки,
контрольные и дедлайны, утренние и вечерние напоминания. Работает и в личном
диалоге с одним учеником, и в общем чате класса.

## Возможности

- `/today`, `/tomorrow`, `/week` — расписание на день/неделю с учётом звонков
- `/bells` — расписание звонков и сколько осталось до конца текущего урока или перемены
- `/homework` — домашние задания, отметка «выполнено» — своя у каждого ученика
- `/grades` — оценки, средний балл по предметам и общий
- `/events` — контрольные, экзамены, дедлайны с обратным отсчётом до даты
- `/timezone` — часовой пояс чата, от него зависит время дайджеста
- утренний и вечерний дайджест в чат: расписание, что сдавать, что не забыть
- управление кнопками (inline-клавиатура), печатать команды вручную не обязательно

Расписание, домашка и события общие для всего чата — добавлять и удалять их
может любой участник, отдельной роли старосты нет: это соответствует тому, как
обычно живёт настоящий чат класса. Оценки видит и редактирует только тот, кто
их добавил. Если в общем чате написать боту что-то вне сценария, он промолчит,
чтобы не мешать обычной переписке — в личном диалоге вместо этого подскажет
`/help`.

## Структура

```
maxbot/
  api/        клиент Bot API MAX — HTTP, лимиты запросов, типы, inline-клавиатуры
  domain/     бизнес-логика без привязки к API и БД: даты, звонки, расписание, дз, оценки, события
  storage/    SQLite (aiosqlite): схема и запросы
  bot/        маршрутизация апдейтов, обработчики команд/кнопок/сценариев, планировщик дайджестов
  config.py   настройки из переменных окружения / .env
  __main__.py точка входа
tests/        pytest
```

## Запуск

1. Получите токен бота в MAX: раздел «Чат-боты» → создать бота → скопировать токен.
2. `cp .env.example .env` и впишите `MAX_BOT_TOKEN`.
3. Установите зависимости:
   ```
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
4. Запустите: `python -m maxbot`.

По умолчанию бот работает через long polling — этого достаточно для разработки.
Для продакшена нужен webhook: `MAX_MODE=webhook`,
`MAX_WEBHOOK_URL=https://ваш-домен/max/webhook`. MAX требует HTTPS и не примет
самоподписанный сертификат; если сертификат Минцифры не установлен в
системное хранилище, укажите путь к нему в `MAX_CA_BUNDLE`.

## Тесты

```
pip install -r requirements-dev.txt
python -m pytest
```

83 теста покрывают разбор дат и расписания звонков, лимиты клавиатуры, слой
хранения и разбор событий Bot API.

## Что учтено из особенностей API MAX

- запросы идут на `platform-api2.max.ru`, токен передаётся в заголовке
  `Authorization`, а не в query-параметрах
- не больше 2 сообщений в секунду в один чат и 30 запросов в секунду всего —
  клиент сам выдерживает паузы
- повтор запроса при 429/5xx с нарастающей задержкой (учитывает `Retry-After`)
- текст длиннее 4000 символов режется на несколько сообщений по границам строк
- лимиты inline-клавиатуры (до 30 рядов, до 210 кнопок, до 7 кнопок в ряду —
  или 3, если это `link`/`open_app`/`request_contact`/`request_geo_location`)
  проверяются до отправки, а не по ответу сервера
