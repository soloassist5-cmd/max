# Школьный бот-помощник для MAX

Бот для мессенджера MAX: расписание уроков и звонков, домашние задания, оценки,
контрольные и дедлайны, утренние и вечерние напоминания, а также ИИ-помощник на
GigaChat. Работает и в личном диалоге с одним учеником, и в общем чате класса.

## Возможности

- `/today`, `/tomorrow`, `/week` — расписание на день/неделю с учётом звонков
- `/bells` — расписание звонков и сколько осталось до конца текущего урока или перемены
- `/homework` — домашние задания, отметка «выполнено» — своя у каждого ученика
- `/grades` — оценки, средний балл по предметам и общий
- `/events` — контрольные, экзамены, дедлайны с обратным отсчётом до даты
- `/timezone` — часовой пояс чата, от него зависит время дайджеста
- утренний и вечерний дайджест в чат: расписание, что сдавать, что не забыть
- управление кнопками (inline-клавиатура), печатать команды вручную не обязательно

### ИИ-помощник (GigaChat)

- `/ask` — объяснить тему или разобрать задачу. Если вопрос похож на домашнее
  задание, бот сначала показывает ход решения, а не готовый ответ
- `/quiz` — тест по любой теме: вопросы с вариантами ответа приходят кнопками,
  после каждого — пояснение, в конце счёт
- `/check` — проверка своей работы: бот спрашивает предмет, задание и решение,
  а в ответ даёт оценку, разбор ошибок и совет
- `/find` — поиск по материалам класса: «когда контрольная по химии», «что задали
  по алгебре». Ответ строится только по расписанию, домашке и событиям из чата

Тесты и проверка работ используют структурированный вывод GigaChat
(`response_format: json_schema`), поэтому ответ модели разбирается по схеме, а не
угадывается из текста. Ответ всё равно проверяется на нашей стороне: вопросы с
битым номером правильного варианта отбрасываются, оценка зажимается в 1–5.

Без `GIGACHAT_AUTH_KEY` бот работает как обычно, а ИИ-раздел сообщает, что его
нужно настроить.

Расписание, домашка и события общие для всего чата — добавлять и удалять их
может любой участник, отдельной роли старосты нет: это соответствует тому, как
обычно живёт настоящий чат класса. Оценки видит и редактирует только тот, кто
их добавил. Если в общем чате написать боту что-то вне сценария, он промолчит,
чтобы не мешать обычной переписке — в личном диалоге вместо этого подскажет
`/help`.

## Структура

```
maxbot/
  api/        клиент Bot API MAX — HTTP, лимиты запросов, типы, inline-клавиатуры
  ai/         клиент GigaChat (OAuth-токен, чат) и прикладной слой: вопросы, тесты, проверка, поиск
  domain/     бизнес-логика без привязки к API и БД: даты, звонки, расписание, дз, оценки, события
  storage/    SQLite (aiosqlite): схема и запросы
  bot/        маршрутизация апдейтов, обработчики команд/кнопок/сценариев, планировщик дайджестов
  config.py   настройки из переменных окружения / .env
  __main__.py точка входа
tests/        pytest
```

## Запуск

1. Получите токен бота в MAX: раздел «Чат-боты» → создать бота → скопировать токен.
2. `cp .env.example .env` и впишите `MAX_BOT_TOKEN`. Для ИИ-раздела туда же
   добавьте `GIGACHAT_AUTH_KEY` — это Authorization key из личного кабинета
   GigaChat API (base64 от `Client ID:Client Secret`).
3. Установите зависимости:
   ```
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
4. Запустите: `python -m maxbot`.

По умолчанию бот работает через long polling — этого достаточно для разработки.
Для продакшена нужен webhook: `MAX_MODE=webhook`,
`MAX_WEBHOOK_URL=https://ваш-домен/max/webhook`. MAX требует HTTPS и не примет
самоподписанный сертификат; если сертификат Минцифры не установлен в
системное хранилище, укажите путь к нему в `MAX_CA_BUNDLE`.

Запускать нужно из корня проекта: оттуда бот читает `.env` и находит пакет
`maxbot`. На старте он проверяет токен запросом `GET /me` и, если токен неверный,
сразу останавливается с понятным сообщением, а не уходит в бесконечные попытки.

## Запуск на сервере

Docker:

```
cp .env.example .env   # вписать токены
docker compose up -d
docker compose logs -f
```

systemd (бот лежит в `/opt/maxbot`, виртуальное окружение — в `/opt/maxbot/.venv`):

```
sudo useradd --system --home /opt/maxbot maxbot
sudo cp deploy/maxbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now maxbot
journalctl -u maxbot -f
```

## Тесты

```
pip install -r requirements-dev.txt
python -m pytest
```

131 тест покрывает разбор дат и расписания звонков, лимиты клавиатуры, слой
хранения, разбор событий Bot API, клиент GigaChat (кэш токена, обновление по
401, повторы при 429) и сценарии ИИ-раздела целиком — от команды до итогов
теста. Сетевые вызовы в тестах подменяются заглушками, так что ключи не нужны.

## Что учтено из особенностей API MAX

- запросы идут на `platform-api2.max.ru`, токен передаётся в заголовке
  `Authorization`, а не в query-параметрах
- не больше 2 сообщений в секунду в один чат и 30 запросов в секунду всего —
  клиент сам выдерживает паузы
- повтор запроса при 429/5xx с нарастающей задержкой (учитывает `Retry-After`)
- текст длиннее 4000 символов режется на несколько сообщений по границам строк
- лимиты inline-клавиатуры (до 30 рядов, до 210 кнопок, до 7 кнопок в ряду —
  или 3, если это `link`/`open_app`/`request_contact`/`request_geo_location`)
  проверяются до отправки, а не по ответу сервера

## Что учтено из особенностей GigaChat API

- токен доступа живёт 30 минут: он кэшируется в памяти и обновляется заранее,
  а на 401 запрашивается заново и запрос повторяется
- `expires_at` приходит то в секундах, то в миллисекундах — разбираются оба формата
- системное сообщение всегда одно и идёт первым, иначе API отвечает 422
- повторы при 429 и 5xx с нарастающей паузой; 4xx не повторяются
- обоим сервисам (MAX и GigaChat) может понадобиться сертификат Минцифры,
  поэтому `GIGACHAT_CA_BUNDLE` по умолчанию берёт значение `MAX_CA_BUNDLE`
